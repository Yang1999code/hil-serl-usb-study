# 官方 HIL-SERL 精简

来源：`rail-berkeley/hil-serl` 和 arXiv:2410.21845。

## 系统在解决什么

真机视觉 RL 通常慢、奖励难写、乱探索会撞硬件。HIL-SERL 用四件事把它压到大约 1 到 2.5 小时：

1. 少量成功演示打底。
2. 训练中人随时纠正。
3. 图像二分类器给稀疏奖励，不手写 dense reward。
4. 用 RLPD 对半混合演示数据和在线数据。

官方 USB 任务还是多阶段：先抓 USB，再插入。分类器常用侧视裁剪；策略额外看两路腕部相机。

## 代码怎么跑起来

1. 起 Franka 阻抗控制器和 Flask 服务。
2. 改 `SERVER_URL`、相机串号、图像裁剪、`TARGET_POSE` 和安全盒。
3. `record_success_fail.py` 采正负样本，训奖励分类器。负样本要覆盖“插错口、只插一半、拿在旁边”这类假阳性。
4. `record_demos.py` 录大约 20 条成功演示。
5. 同时开 `run_actor.sh` 和 `run_learner.sh`。前期每局都可能要干预，后期逐渐放手。
6. 用 `--eval_checkpoint_step` 评测。

Flask 常用接口：`getstate`、`pose`、`getpos_euler`、`jointreset`、夹爪开关。飞书笔记暴露的接口集合和这里同族。

## USB 例子里的包装顺序

`TrainConfig.get_environment()` 实际叠了这些 wrapper：

1. `USBEnv`：Franka 环境，侧视分类器和侧视策略共用同一路相机。
2. `SpacemouseIntervention`：人接管。
3. `RelativeFrame`：相对坐标系。
4. `Quat2EulerWrapper`
5. `SERLObsWrapper`：整理本体感觉。
6. 可选 `MultiCameraBinaryRewardClassifierWrapper`
7. `GripperPenaltyWrapper`：乱开夹爪给小惩罚。

奖励判定不是只看分类器。USB 配置里还要求夹爪开度大于阈值，减少“没抓住也报成功”。
